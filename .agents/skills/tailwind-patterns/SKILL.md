# Tailwind CSS Architecture & Best Practices

Tailwind CSS provides a utility-first CSS framework for rapid, maintainable UI construction.

---

## 1. Design Token Architecture via CSS Variables

Define semantic design tokens in `globals.css` using HSL or OKLCH CSS variables, allowing dynamic theming and seamless dark mode switching:

```css
@tailwind base;
@tailwind components;
@tailwind utilities;

@layer base {
  :root {
    --background: 0 0% 100%;
    --foreground: 240 10% 3.9%;
    --card: 0 0% 100%;
    --card-foreground: 240 10% 3.9%;
    --popover: 0 0% 100%;
    --popover-foreground: 240 10% 3.9%;
    --primary: 240 5.9% 10%;
    --primary-foreground: 0 0% 98%;
    --secondary: 240 4.8% 95.9%;
    --secondary-foreground: 240 5.9% 10%;
    --muted: 240 4.8% 95.9%;
    --muted-foreground: 240 3.8% 46.1%;
    --accent: 240 4.8% 95.9%;
    --accent-foreground: 240 5.9% 10%;
    --destructive: 0 84.2% 60.2%;
    --destructive-foreground: 0 0% 98%;
    --border: 240 5.9% 90%;
    --input: 240 5.9% 90%;
    --ring: 240 5.9% 10%;
    --radius: 0.5rem;
  }

  .dark {
    --background: 240 10% 3.9%;
    --foreground: 0 0% 98%;
    --card: 240 10% 3.9%;
    --card-foreground: 0 0% 98%;

  }
}
```

## 2. Configuration (`tailwind.config.ts`)

```typescript
import type { Config } from "tailwindcss"

const config: Config = {
  darkMode: ["class"],
  content: [
    "./pages/**/*.{ts,tsx}",
    "./components/**/*.{ts,tsx}",
    "./app/**/*.{ts,tsx}",
    "./src/**/*.{ts,tsx}",
  ],
  theme: {
    container: {
      center: true,
      padding: "2rem",
      screens: { "2xl": "1400px" },
    },
    extend: {
      colors: {
        border: "hsl(var(--border))",
        input: "hsl(var(--input))",
        ring: "hsl(var(--ring))",
        background: "hsl(var(--background))",
        foreground: "hsl(var(--foreground))",
        primary: {
          DEFAULT: "hsl(var(--primary))",
          foreground: "hsl(var(--primary-foreground))",
        },
        secondary: {
          DEFAULT: "hsl(var(--secondary))",
          foreground: "hsl(var(--secondary-foreground))",
        },
        muted: {
          DEFAULT: "hsl(var(--muted))",
          foreground: "hsl(var(--muted-foreground))",
        },
      },
      borderRadius: {
        lg: "var(--radius)",
        md: "calc(var(--radius) - 2px)",
        sm: "calc(var(--radius) - 4px)",
      },
    },
  },
  plugins: [require("tailwindcss-animate")],
}
export default config
```

## 3. Best Practices & Anti-Pattern Prevention

### Do's
- **Component Colocation**: Keep utility classes directly on HTML/JSX tags.
- **Responsive Prefixes**: Use mobile-first breakpoints (`sm:`, `md:`, `lg:`, `xl:`, `2xl:`).
- **Dark Mode**: Use `dark:` variants attached to CSS variables (`bg-background text-foreground`).
- **Interactive States**: Always pair `hover:` with `focus-visible:` and `active:` states for accessibility.

### Don'ts (@apply Abuse)
- **Do NOT** use `@apply` to recreate old-fashioned CSS classes (`.my-button { @apply px-4 py-2 bg-blue-500 ... }`). This destroys Tailwind's deduplication benefits and reintroduces CSS naming overhead. Instead, extract React components or use CVA.
